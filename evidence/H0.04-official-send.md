## Fuentes nuevas y reconsulta
- https://openai.com/policies/row-terms-of-use/ vigente 2026-01-01, sección Using our Services: acceso/uso condicionado al cumplimiento; restricción explícita de extracción automática/programática y de interferencia, elusión de límites y medidas protectoras. No se identifica prohibición textual categórica de enviar texto por extensión, ni autorización específica de esa modalidad. No dictamen jurídico.
- https://github.com/openai/mcp-extensions/blob/main/docs/spec.md secciones Platform Support, Thread Entrypoint, Deep Links, Prompt Target and Send Behavior: nueva verificación directa de la fuente formal. Cada thread entrypoint tiene instancia propia y apertura manual por usuario; deep links apuntan a páginas del plugin global, no a una conversación destino. ui/message admite target active/new y send booleano; sin ID/URL de chat arbitrario. El soporte extendido en web corresponde a Work, excluye ChatGPT clásico; escritorio/iOS según matriz, comprobar disponibilidad concreta en chat normal y proyecto. No asumir que el contrato formal autoriza disparos remotos/desatendidos.
- https://developers.openai.com/plugins/build/extensions y https://developers.openai.com/plugins/build/chatgpt-ui: integración oficial embebida en host, equivalencia ui/message con sendFollowUpMessage. https://developers.openai.com/plugins/reference: firma legacy con prompt y scrollToBottom sin selector de conversación.
- https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html: SDK de MCP Apps describe envío por interacción de usuario y comunicación app-chat; host puede rechazar. No prueba comportamiento del host ChatGPT bajo órdenes remotas o temporizador.
- https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages: tráfico que parece automatizado puede producir avisos de actividad inusual; no intentar eludirlos.
## Resultado
Existe una vía oficial de envío al chat que aloja una UI MCP. La hipótesis nueva es un plugin con instancia por conversación, no un Site externo que direcciona cualquier chat. No es solución probada: apertura manual, disponibilidad en chats normales, ciclo de vida de instancias, recepción remota, permiso para disparar sin interacción y confirmación de finalización siguen sin establecerse. El usuario no acepta prototipo parcial como producto; solo merece una prueba focalizada si puede aclarar el transporte.
Prueba acotada por vía documentada: en entorno con autoría de plugins Sites, crear únicamente widget privado de prueba con envío a conversación anfitriona mediante ui/message y gesto humano, sin lectura de chat; confirmar capacidades del host, identidad y recepción una vez en dos chats de prueba existentes designados (uno proyecto), nunca target new; verificar si una instancia de conversación se puede abrir y permanecer activa y si documentación autoriza recepción remota y activación desatendida. No ejecutar temporizador o integración no documentada; no usar endpoints privados, manipulación DOM, credenciales, elusión de controles ni tareas programadas. Solo continuar hacia remoto/auto si se identifica permiso/mecanismo aplicable. Aquí no se expone autoría/despliegue Sites ni control de navegador: la revisión de herramientas confirma solo lectura de pestañas y gestión de plugins, no creación ni envío. No se creó widget ni ejecutó prueba; no se solicitó soporte. Para extensión externa, sigue pendiente aclaración oficial. Esta prueba potencial no satisface por sí misma envío externo ni reemplaza el objetivo.
