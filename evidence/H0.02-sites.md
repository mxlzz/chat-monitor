# H0.02 — Anexo: ChatGPT Sites y plugin alojado
Fecha: 2026-11-25. Base: b264f01308131fb03a5e19ca9cdac839e81123e6. Revisión documental a petición del usuario, no auditoría completa H0.02 ni prueba funcional.
## Fuentes oficiales
- https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites — disponible Plus/Pro, construcción y edición consumen cuota Codex, hosting actualmente incluido, límites compartidos, base de datos hasta 10 GB por Site. Despliegue privado por defecto; Site alojado con URL. Túneles a red privada en despliegue gradual para espacios elegibles: no establecer disponibilidad personal.
- https://developers.openai.com/training/walkthroughs/building-a-shareable-site — confirma persistencia de datos y archivos en Site.
- https://help.openai.com/en/articles/20001547-hosting-a-plugin-with-chatgpt-sites — MCP hospedado, herramientas de lectura/escritura, publicación por propietario, instalación y conexión separadas, ejemplo de dashboard con actualizaciones desde chat. Compartir plugin alojado no disponible directamente a otros usuarios en cuentas personales; no afecta al uso individual. Pruebas con datos sintéticos antes de acceso.
- https://help.openai.com/en/articles/10169521-projects-in-chatgpt — apps conectadas disponibles en chats de proyectos; selección por menú o nombre; posible confirmación al acceder fuera del proyecto. No prueba disponibilidad concreta del plugin en chats ya existentes.
- https://help.openai.com/en/articles/20001495-managing-app-permissions-in-chatgpt — escrituras pueden exigir aprobación; opciones dependen de app/cuenta/acción. No presumir permisos persistentes ni solicitar acceso general.
- https://developers.openai.com/plugins/build/mcp-events — eventos MCP solo Work web, Work desktop Cloud y dots. No sirven como disparador de chat normal bajo objetivo actual.
- https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt — tareas recurrentes en Chat hasta una vez por hora en planes elegibles, Plus 5 activas; evento webhook en Work. Tarea asociada a chat no implica que pueda reanudar cualquier chat existente ni control por API desde Site. Consumo de cuota y posibles confirmaciones. Verificar identidad/contexto y acceso a plugin en futura prueba autorizada.
- https://openai.com/policies/chatgpt-sites-terms/ (actualización 2026-11-06) — complementa términos generales, obligaciones de seguridad y privacidad; no autoriza extracción programática de ChatGPT ni envío externo a chats normales.
- https://help.openai.com/en/articles/20001337-understanding-responsibilities-for-your-chatgpt-sites — editores tienen acceso a DB y recursos; mantener privado y sin otros editores.
## Arquitectura candidata, no adoptada
Site privado con BD nativa; plugin MCP mínimo para publicar y consultar estados propios deliberadamente autorizados. Sin Notion/Sheets/Firebase ni máquina Windows como dependencia del dashboard. Registro manual del alias y enlace original privado (no enlace compartido público). Herramienta publish_report(agent_alias, report_id, status, summary, next_action): validar alias permitido, tamaño, enumeración y duplicados; sello temporal servidor, historial, respuesta de confirmación; ningún historial completo, identificadores privados en GitHub, cookies, endpoints privados, scraping o credenciales. Herramienta read_pending_instruction opcional para leer una orden de trabajo depositada por usuario, no ejecutarla como trigger; el chat necesita estar activo para consultar. Botón abrir/copiar, pegado y envío humano. Estado publicado no prueba finalización de respuesta; sin datos nuevos indicar antigüedad y estado de transporte desconocido.
## Evaluación R1–R6
R1 parcial: alias y enlaces originales registrados manualmente; identidad no verificada. R2 parcial: resúmenes y estado declarado, no última respuesta literal ni generación observada. R3 parcial: apertura/copia manual; envío en UI oficial por usuario. R4 no resuelto: MCP Events excluido, no mecanismo oficial de reanudación desde Site; sondeo por tareas nativas a estudiar pero sin garantía. R5 prometedor: privado y alojado, verificar Safari iPhone, autenticación y revocación. R6 prometedor: coste marginal hosting incluido actualmente, cuota Codex para creación, límites de uso; dependencia de proveedor, comprobar exportación y reproducibilidad. Servicio propietario; licencia de distribución del código a determinar, no revisión de código fuente.
## Prueba mínima propuesta, posterior a autorización para prototipo parcial
A. Crear Site privado con registros ficticios y una sola herramienta de escritura restringida; comprobar validación y duplicados. B. Publicar en privado para instalar plugin; comprobar visibilidad y permisos. C. Dos chats de prueba, uno dentro de proyecto, enviar tres reportes sintéticos y verificar persistencia, actualización, identidad del alias, confirmaciones, rechazo de alias no registrado y ausencia de filtración. D. Comprobar Safari iPhone/Windows, acceso no autorizado rechazado y enlace/copiar, sin activar investigaciones existentes. E. En ensayo separado, autorizado, comprobar si tarea nativa Chat en conversación de prueba puede consultar una orden del plugin y publicar resultado conservando identidad/contexto. No asumir control del programador desde Site, disparador inmediato ni disponibilidad de cuota; detener ante confirmación o falta de permiso. No ejecutar ninguna prueba real todavía.
## Resultado
Sites es candidato preferente para monitoreo parcial por simplicidad y hosting, no demuestra cumplimiento completo ni justifica saltar H0/H1. H0.02 sigue pendiente respecto a otros candidatos. No se creó Site, plugin ni tareas ni se concedieron permisos. Criterio de este anexo: fuentes primarias, alcance, brechas, costes, riesgos y test falsable. Decisión de arquitectura y alcance parcial pendiente de H0.03 y aprobación del usuario.

## Intento de prueba nativa de continuidad
Se intentó crear una tarea de una sola ejecución con un contexto sintético previo no incluido en el prompt, sin herramientas ni cambios de proyecto, para comparar recuperación de contexto y ubicación de respuesta. El servicio rechazó la creación por límite de tareas activas del plan. No se creó ninguna tarea ni se ejecutó el ensayo; no hay resultado respecto de continuidad o identidad de chat. Requiere disponibilidad de una plaza y autorización para pausar cualquier tarea existente; no modificar tareas sin permiso. La investigación documental H0.02 puede continuar por separado.

## 2026-11-25 — Aclaración y revisión de envío directo desde Sites
El usuario aclara que no quiere crear automatizaciones: la prueba solicitada es Site → envío inmediato de «Continúa» a cada chat normal existente seleccionado. El intento anterior de tarea nativa no responde a esta prueba; no repetirlo ni pausar tareas. No se elimina su resultado negativo del historial.
Fuentes consultadas el 2026-11-25:
- https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites y https://help.openai.com/en/articles/20001547-hosting-a-plugin-with-chatgpt-sites: el Site aloja herramientas MCP invocadas desde chat, no documentan una operación para enviar mensajes al chat normal existente seleccionado desde el Site independiente. Creación de Site desde Work/Codex.
- https://developers.openai.com/plugins/build/mcp-events: eventos solo Work web/desktop Cloud y dots; excluidos como destinos.

Es una interfaz embebida en la conversación anfitriona, no una API de direccionamiento a otros chats desde sitio web; no se documenta parámetro para seleccionar chat arbitrario. Validar por separado si el plugin alojado soporta UI MCP en chat normal; no equivale a R3 remoto ni R4.
- https://developers.openai.com/workspace-agents/trigger-runs: API de agentes publicados de workspace, no chats personales normales. No cumple objetivo.
Resultado: revisión de contratos y herramientas disponibles, no prueba de ejecución. No hay acción de creación/despliegue Sites ni envío a chat arbitrario expuesta en el entorno actual. No se creó Site, no se envió mensaje ni se modificó automatización alguna. La ruta directa queda sin mecanismo autorizado establecido. Una prueba de capacidad en Work con @Sites puede solicitar exclusivamente enumerar las acciones oficiales disponibles para un chat de prueba y, solo si hay una operación documentada, enviar texto sintético una sola vez a ese chat y verificar identidad/recepción. Si no existe, informar bloqueo sin simular éxito, sin endpoints privados ni automatización de UI. Alternativas parciales: abrir enlace original y copiar texto para envío humano, o widget de seguimiento en cada conversación anfitriona. No declarar continuidad automática.

## 2026-11-25 — contraste con investigación realizada desde Sites
El usuario aportó el resultado de una revisión documental independiente de esta conversación, realizada desde el entorno de Sites. No identificó API oficial para enviar un mensaje a un chat normal existente por URL/ID. No creó prototipo, no ejecutó ni simuló envío. Reportó que ui/message admite active/new, no destino arbitrario. Se contrastó con documentación primaria consultada el 2026-11-25: https://developers.openai.com/plugins/reference (firma sendFollowUpMessage con prompt y scrollToBottom; sin selector de chat), https://developers.openai.com/plugins/build/chatgpt-ui (bridge dentro de iframe de ChatGPT y equivalencia ui/message), https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites (Sites y sus integraciones). La distinción exacta active/new fue reportada por la otra revisión, no localizada independientemente en el texto consultado de la referencia; no se infiere capacidad de direccionamiento arbitrario. La coincidencia documental refuerza el bloqueo de envío directo; no es prueba experimental ni prueba de inexistencia universal. No se publica enlace privado a Notion ni datos de conversaciones. Mantener Sites como candidato para monitoreo por publicación voluntaria y enlace/copia manual. Investigar por separado alternativas locales permitidas para envío, sin tareas programadas para esta prueba. H0.02 permanece pendiente; no se cambia el objetivo ni se aprueba desarrollo parcial aún.
