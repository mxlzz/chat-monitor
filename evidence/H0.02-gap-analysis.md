## Inspección estática ChatCMD
Revisión fijada e604ac8cb53322082887f97efdcdd647193de768 (MIT; 2026-09-25). Prefijo de fuente: https://github.com/int04/ChatCmd/blob/e604ac8cb53322082887f97efdcdd647193de768/

- chatgpt-extension/background-tabs.js: gestión de apertura, reutilización y vínculo por identidad de pestañas. background-io.js: valida origen, reconoce ID en segmento de conversación y contempla URL de entrada a proyecto para crear conversación. No garantiza identificación de todas las variantes de URL ni uso de proyectos reales.
- src/api/chatgpt.rs: seguimiento asociado a tarea previamente vinculada. web/src/chatgpt/ChatGptTaskComposer.tsx usa identidad existente; web/src/chatgpt/ChatGptConversation.tsx contempla URL de proyecto para conversación nueva. No se localizó flujo de alta manual por URL de chat arbitrario en archivos inspeccionados.
- src/api/chatgpt_native.rs: el backend registra un turno de conversación nativa y crea tarea si no hay vínculo; permite conceptualmente incorporar chats externos a ChatCMD por captura. content-chatgpt-native.js y background-io.js muestran captura y transferencia de contenido, no alta manual. Esta ruta depende de extracción programática, excluida sin autorización; no reutilizarla para integración real.
- src/api/chatgpt_native_tests.rs: pruebas de idempotencia, rechazo de identidad suplantada, conversación existente y aislamiento concurrente. chatgpt-extension/content-chatgpt.test.cjs: pruebas de estado ocupado, identidad, errores y recuperación. No se ejecutaron ni se verificó CI. No demuestran preservación de borradores, confirmación de finalización para nuestros requisitos, ni semántica READY, cancelación al intervenir humano, límites propios y pausa global. No prueba en iPhone ni con proyecto existente.
Conclusión: ChatCMD es referencia técnica más próxima de los candidatos estudiados, no producto listo ni permiso de uso. Una adaptación requeriría eliminar captura/observación de respuestas y registro automático, añadir alta manual de chats y reportes voluntarios, validar operación remota y estados. No se estima esfuerzo de código sin autorización y revisión adicional. No ejecutar ni copiar lógica de envío real hasta pasar puerta de permiso.

## Conectividad Site–Windows
https://help.openai.com/en/articles/20001606-connecting-chatgpt-sites-to-private-services-with-tunnels consultado 2026-11-25: túneles oficiales en despliegue para espacios Enterprise elegibles, requieren administrador. No asumir disponible en Plus.
https://tailscale.com/docs/features/tailscale-serve: Serve conecta dispositivos de la misma tailnet al servicio local, no convierte servidor cloud de Sites en miembro. https://tailscale.com/docs/install/ios confirma soporte iOS. Tailscale resuelve panel local o escritorio remoto, no por sí solo el puente Sites cloud→PC.
Arquitectura condicional de canal de datos (no autorización de envío): Site aloja registros/reportes y, si existe API autorizada y autenticación máquina-a-máquina para el Site propio, PC podría iniciar conexión saliente y recoger órdenes; no publicar puertos ni compartir cookies. Disponibilidad de API privada y autenticación específica no establecida; no construir ni ejecutar despachador hacia chat. Si se mantiene envío humano, no se necesita canal de comandos: Site abre enlace y copia texto. Si se requiere control de escritorio, evaluar acceso remoto humano a través de tailnet.
## Decisión provisional
Priorizar Sites para reportes y alta manual; conservar ChatCMD y ChatSequel como referencias documentales, no instalar. Brecha decisiva no es sólo código: permiso del servicio para envío programático, además de confirmación de finalización, seguridad e identidad. Próxima acción H0.02: concluir revisión de candidatos restantes (MultiChat Monitor, WebUI Bridge, Chat Alert, RustDesk, conectores pertinentes) y H0.03 comparar alcance completo vs parcial y auditar. No cambiar alcance ni crear Site/automatizaciones sin aprobación pertinente. No se subieron datos privados.
