# Work o Codex como origen de un mensaje a Chat normal

26 de noviembre de 2026. Revisión documental solicitada. No hubo acceso a conversaciones ni envío real.

El [contrato ui/message](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#prompt-target-and-send-behavior) ofrece destino activo o nuevo. Los [comandos de Codex](https://learn.chatgpt.com/docs/developer-commands) se dirigen a sesiones de Codex. [MCP Events](https://developers.openai.com/plugins/build/mcp-events) enumera Work y dots como receptores. No se identificó una interfaz directa para seleccionar por ID otro chat normal existente.

[Cloud Browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt) puede operar sitios compatibles desde Work en el móvil y requiere inicio de sesión separado. [Control de Edge](https://learn.chatgpt.com/docs/chrome-extension) permite actuar en sitios compatibles con sesión local desde Work/Codex. Existe un [reporte específico en Windows](https://github.com/openai/codex/issues/59803) con corroboración de otro usuario en Edge: detectar la pestaña no bastó para acceder al contenido. Son informes de terceros, no una regla universal ni evidencia de envío. [Remote](https://learn.chatgpt.com/docs/remote-connections) da acceso al entorno de la PC, sin establecer que chatgpt.com admita control. La comprobación siguiente requiere designar un chat normal de prueba sin contenido de investigación y verificar únicamente si el host habilita el cuadro de mensaje. No subir URL o identificador a GitHub. Una denegación del host cierra esa prueba. Solo una entrega observada una vez en el hilo original tras autorización permite afirmar que funciona.
